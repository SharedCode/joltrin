    How it works.

    You set the rule

    A rule names the agent, the tool, the resource and what must be true first. It expires, you can edit it, and revoking it blocks the next attempt.

          What this does not do 
          
    It cannot stop an agent that has its own route to the target system. It only protects actions that run through the executor's check. A receipt shows a decision was made. It does not show the action ran. Preferences are sealed on disk and kept out of decisions and receipts, but the owner's machine and the engine still see them, so this is data minimization and not a zero-knowledge system.

    RUN IT WITH AN MCP AGENT
    
              
    git clone https://github.com/SharedCode/joltrin && cd joltrin
go run ./examples/private_intent demo        # scripted run, no setup
go run ./examples/private_intent init ./pi   # then add the printed config to your MCP client
go run ./examples/private_intent attest ./pi prod/orders
go run ./examples/private_intent approve ./pi orders
